# Task 4 · Schedules and backup status

Read the design, common plan and finalized queue schema. Task 1 owns the baseline. In the isolated checkout use injected clocks, fake queue actions and disposable local roots. The runtime already has an owner/installation mutex, but concurrent UI queue writers do not participate in it.

**Deliverable.** A source user can choose a folder and a daily local time, see when it will run next, update/disable it, close the app and have the existing signed-in runtime do the work. The dashboard shows latest attempt, last successful originals backup and optional media status separately. The screen explains that both computers must be on, signed in and connected.

**Files.** Add `src/shared/NetCrate.Schedule.ps1` (dot-source from `NetCrate.Workflow.psm1`), `src/desktop/ScheduleView.cs`, `tests/installation/Test-Schedules.ps1` and `tests/desktop/ScheduleViewTests.cs`. Modify `src/shared/NetCrate.Queue.ps1`, `Invoke-NetCrateRuntime.ps1`, `install/Invoke-SetupAction.ps1`, `src/desktop/setup/WindowsSetupService.cs`, `src/desktop/{GuidedModel,AppModel,WindowView}.cs`, `src/desktop/Build.ps1`, `tests/desktop/GuidedModelTests.cs`, `docs/setup.md`.

**Interfaces.** Bridge actions `ListSchedules`, `SaveSchedule`, `DisableSchedule`, restricted to an installed Source identity. Input is a canonical folder, `TimeOfDay` in HH:mm and an enabled flag. One record per case-insensitive canonical folder, stable schedule ID and revision on edit, with effective time, last consumed occurrence and displayable next due time. Store versioned nonsecret records in Engine/Schedules. `Invoke-NetCrateSchedules($Root,$Settings,[DateTimeOffset]$Now,[TimeZoneInfo]$Zone)` performs a short once-per-runtime-pass scheduler check and calls the same queue admission as manual backup. Use actual Task 2 completion evidence.

- [ ] Add controlled-clock tests for first creation before/after today's time, editing, disabled schedule after restart, several missed days, clock rollback, spring-forward gap, fall-back repeated hour, timezone change and unavailable folder. Pin the chosen semantics: first run is the next occurrence after save; a skipped spring minute runs at the next valid local minute; a repeated hour counts once per local date. Never enqueue before creation or replay days already consumed.
- [ ] Test manual/manual, manual/scheduled, concurrent scheduler ticks and crash windows around admission/cursor writes. Assert exactly one active originals job per folder and one catch-up on return. Inject retry after a persisted snapshot and verify no second confirmed original; an interrupted media transfer must not reset the originals result. Add dashboard cases for success followed by failed/queued attempt and media failure.
- [ ] Run the new scheduler fixture before implementation and confirm the missing behavior. Add a short-lived named queue-admission lock scoped to the installation so action writers and runtime share one critical section (never hold it across a backup). Track eligible work by local date, resolve the most recent due occurrence and advance only after durable idempotent enqueue or assignment to an existing active originals job. Record the stable occurrence/job association before cursor advancement so concurrent/replayed calls cannot enqueue it twice. Editing/disable under the same lock changes future admission; it can leave already running work to finish. Re-read the record inside the lock. Validate canonical paths using the mode-aware Task 2 helper.
- [ ] Call scheduler before normal queue drain in the existing owner runtime; pending originals retries use the same durable job and delay. Pause repeat processing when a folder is inaccessible without blocking other schedules. New manual runs after a completed original remain allowed even while media is pending. When an earlier child backup overlaps a scheduled parent folder, serialize actual execution in the existing single runtime.
- [ ] Wire the WPF schedules dialog, its empty list, folder/time selection, enable/disable, next-run display and persistent error/status hints. Read all relevant queue history per folder for last successful backup, separate current attempt and media result, and label a legacy completion time as unknown if no reliable old timestamp exists. Display local times with zone and include full date. Add fake-service view tests and update setup docs.
